## Metodik

| Ord | Förklaring |
| --- | --- |
| Agilt / Agil metodik | Samlingsnamn för arbetssätt byggda på korta iterationer, kontinuerlig feedback och förändringsbenägenhet — istället för att planera allt i förväg. Scrum och Kanban är konkreta exempel. |
| Backlog (Produktbacklog) | En prioriterad lista över allt som ska göras i ett projekt — funktioner, buggar, förbättringar. Ägs och underhålls av Product Owner. |
| Cykeltid | I Kanban: hur lång tid en uppgift tar från att den påbörjas till att den är klar. |
| Daily Scrum / Daglig standup | Ett kort (~15 min) dagligt möte där teamet synkar: vad gjordes igår, vad görs idag, finns hinder. |
| Genomloppstid (lead time) | I Kanban: hur lång tid en uppgift tar från att den skapas till att den är klar, inklusive väntetid. |
| Iteration | En avgränsad, upprepad arbetscykel — planera, bygga, testa, utvärdera — innan nästa cykel påbörjas. |
| Kanban | En agil metod som visualiserar arbetsflödet på en tavla med kolumner (t.ex. Att göra / Pågår / Klart), utan fasta tidsboxar som Scrums sprintar. |
| Konsult | En anställd hos ett konsultbolag som hyrs ut för att arbeta hos kundföretag. Se även Underkonsult. |
| Konsultchef | Chef över konsulter på ett konsultbolag — bemanning, kundrelationer, karriärutveckling. Inte samma sak som att vara konsult. |
| MVP (Minimum Viable Product) | Den minsta versionen av en produkt som är användbar nog för att testa en idé på riktiga användare. |
| Product Owner | Äger produktbacklogen och prioriterar vad teamet ska bygga härnäst, utifrån affärsvärde och kundbehov. |
| Retrospektiv (Retro) | Mötet i slutet av en sprint där teamet reflekterar över hur de jobbade och vad som kan förbättras till nästa sprint. |
| Scrum | Ett agilt ramverk där arbetet delas upp i tidsboxade sprintar, med fasta roller (Scrum Master, Product Owner) och återkommande möten (planning, standup, review, retrospektiv). |
| Scrum Master | Faciliterar Scrum-processen — håller i ceremonier och undanröjer hinder för teamet. Inte en chef över teamet. |
| Sprint | En tidsboxad arbetsperiod i Scrum, vanligtvis 1-4 veckor, där teamet levererar ett avgränsat, testat resultat. |
| Sprint Backlog | De uppgifter från produktbacklogen som teamet åtagit sig att göra under en specifik sprint. |
| Sprint Planning | Mötet i början av en sprint där teamet väljer vilka poster från backlogen som ska göras. |
| Sprint Review | Mötet i slutet av en sprint där teamet visar upp vad som byggts för intressenter. |
| Story point | Ett relativt mått på hur komplex eller tidskrävande en uppgift är — används för att uppskatta arbete i agila team istället för att gissa exakta timmar. |
| Test-pyramiden | En modell för hur testerna i ett projekt bör fördelas: många snabba enhetstester i botten, färre integrationstester i mitten, färst end-to-end-tester i toppen. |
| Underkonsult | En konsult som hyrs in via ett annat konsultbolag snarare än direkt av kundens konsultbolag — en mellanhand i uppdraget. |
| User story | En kort beskrivning av en funktion ur användarens perspektiv, ofta i formen "Som [roll] vill jag [göra något] så att [nytta]". |
| V-modellen | En variant av vattenfallsmodellen som kopplar varje utvecklingsfas till en motsvarande testfas — brukar ritas upp som ett V. |
| Vattenfallsmodellen (Waterfall) | En traditionell projektmetod där varje fas (krav, design, utveckling, test, drift) slutförs helt innan nästa påbörjas. Motsatsen till agilt. |
| WIP-gräns (Work in Progress) | I Kanban: gränsen för hur många uppgifter som får vara i en kolumn samtidigt — tvingar teamet att slutföra innan de börjar på nytt. |
